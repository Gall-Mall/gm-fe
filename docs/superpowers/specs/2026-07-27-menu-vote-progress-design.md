# 메뉴 투표 참여 현황 및 완료 화면 유지 설계

## 목표

- 메뉴 투표 화면에서 활성 그룹원 중 투표 완료 인원과 아직 투표 중인 인원을 표시한다.
- 사용자가 자신의 투표를 끝내고 완료 화면으로 이동한 뒤 다른 그룹원의 투표 이벤트가 와도 투표 화면으로 되돌아가지 않게 한다.

## 데이터 기준

- 전체 인원은 그룹 멤버 조회 API가 반환한 활성 멤버 목록 수를 사용한다.
- 완료 인원은 투표 상태 API의 `menuVote.completedUserIds`와 활성 멤버의 `userId`를 대조해 계산한다.
- 투표 중 인원은 `전체 인원 - 완료 인원`으로 계산하며 음수가 되지 않게 한다.
- 서버 완료 목록을 아직 받지 못한 1인 그룹은 현재 사용자의 로컬 전체 투표 완료 상태를 임시 완료 상태로 표시한다.

## 화면

- 메뉴 투표 카드 상단의 진행 정보 영역에 `투표 완료 N명`과 `투표 중 M명`을 작은 상태 배지로 표시한다.
- 기존 후보 진행 번호, 제한 시간, 최종 후보 표시는 유지한다.

## 화면 전환

- 일반적인 투표 상태 동기화는 집계와 완료 사용자 목록만 갱신하고 `MENU_VOTING`이라는 이유만으로 화면을 변경하지 않는다.
- 그룹 진입 또는 초대 가입 후 진행 중 세션을 복원하는 흐름에서만 `MENU_VOTING` 상태를 확인해 메뉴 투표 화면으로 이동한다.
- 따라서 완료 화면에서 WebSocket `MENU_VOTE_UPDATED` 이벤트를 받아도 완료 화면을 유지한다.
- `MENU_SELECTION`, 식당 검색·선택, 완료 상태처럼 서버 단계가 실제로 전진한 경우의 기존 화면 전환은 유지한다.

## 검증

- 메뉴 투표 화면에 완료·진행 인원이 올바르게 표시되는 컴포넌트 테스트를 추가한다.
- 완료 화면에서 투표 갱신 이벤트를 받아도 화면이 유지되는 흐름 테스트를 추가한다.
- 그룹에 다시 진입해 `MENU_VOTING` 세션을 복원하면 투표 화면으로 이동하는 기존 테스트를 유지한다.
- 프론트 전체 테스트와 프로덕션 빌드를 실행한다.
